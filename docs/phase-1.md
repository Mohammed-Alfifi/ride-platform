## قرارات تصميم

**حساب لكل تطبيق.** الرقم نفسه قد يكون راكبا وسائقا، فلكل تطبيق حساب مستقل (`users.audience`). الركاب والسائقون ينشئون حساباتهم بأنفسهم؛ حسابات اللوحة ينشئها مدير فقط.

**عدم كشف أرقام المدراء.** طلب رمز للوحة برقم غير مسجّل يعيد الرد نفسه تماما، لكن لا يُرسل شيء.

**الرموز.** تُخزَّن في Redis مُجزّأة (HMAC مع pepper)، تصلح مرة واحدة، 5 دقائق، 5 محاولات خاطئة كحد أقصى، دقيقة بين كل طلبين، و5 طلبات في الساعة لكل رقم.

**الجلسات.** رمز الوصول JWT لمدة 15 دقيقة يحمل «إصدار الجلسة»؛ رفع الإصدار (خروج من كل الأجهزة، إيقاف، تغيير دور) يُبطل كل الرموز فورا. رمز التجديد عشوائي ويتبدّل مع كل استخدام؛ تقديم رمز مستعمل يُعامل كسرقة ويُنهي العائلة كلها.

**اللوحة لا ترى الرموز.** خادم Next.js يحفظها في ملفات تعريف httpOnly ويمرر الطلبات إلى الـ API (BFF)، فلا يصل إليها أي سكربت في المتصفح.

**عزل الشركاء.** كل استعلام إداري يمر عبر `partnerScope`؛ الوصول لسجل شريك آخر يعيد «غير موجود» لا «ممنوع»، حتى لا يُكشف وجوده.

## ما يلزم قبل البيئة التجريبية

1. اختيار مزوّد استضافة بمنطقة سعودية وإنشاء قاعدة PostgreSQL + PostGIS و Redis.
2. بناء صورتي Docker (`apps/api/Dockerfile`, `apps/admin/Dockerfile`) وربط النشر التلقائي من فرع `main`.
3. مزوّد SMS سعودي (مثل خدمات الرسائل المرخّصة) وتسجيل اسم المرسل.
4. أرقام اختبار ثابتة لمراجعي المتاجر عبر `OTP_TEST_PHONES`.
